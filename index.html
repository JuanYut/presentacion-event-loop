El problema

JavaScript hace una sola cosa
a la vez.

Si algo tarda (un timer, una petición al servidor),
todo lo demás se queda esperando y la página se congela.

La solución

No esperar.

JS delega lo que tarda, sigue con lo demás
y lo retoma cuando ya está listo.

¿Y quién decide
cuándo retomarlo?

Event Loop

Dato curioso

JavaScript no inventó
el Event Loop.

Lo heredó del navegador, que ya funcionaba con un bucle de eventos.
Y no fue lo único que heredó… ya lo verán.

¿Cómo llegamos aquí?

  1. 1995 Nace JavaScript en Netscape, dentro del navegador. Ya trae setTimeout.
  2. 2009 Node.js lleva el Event Loop fuera del navegador: al servidor.
  3. 2015 Llegan las Promises y, con ellas, una segunda cola: las microtasks.
  4. 2017 async/await: las mismas Promises, escritas como código normal.

Para resolverlo,
primero 3 cosas
de JavaScript…

JS es síncrono:
Tiene un solo hilo, así que ejecuta el código línea por línea, en orden

Pregunta

¿Cuál es la diferencia entre síncrono y asíncrono?

Pista

Una llamada: no cuelgas hasta que te contestan.
Un WhatsApp: lo mandas y sigues con tu vida.

Síncrono:
Código que se ejecuta línea por línea, al instante. Bloquea, porque espera a que todo termine.

console.log('1');
console.log('2');  // Espera a que 1 termine

Asíncrono:
Código que se programa y ejecuta después.
No bloquea.

setTimeout(() => console.log('2'), 0);
console.log('1');  // No espera a setTimeout
// Output: 1, 2

JS maneja asincronía con el Event Loop:
Los callbacks esperan a que el hilo esté libre

Callback: una función que le pasas a otra para que la ejecute después.

¿Y los demás lenguajes?

Casi todos son síncronos por defecto. Lo que cambia es cómo evitan quedarse bloqueados.

EstrategiaLenguajesLa idea
Varios hilos Java, C#, C++ Lo que tarda se va a otro hilo. Paralelismo real… y bugs muy difíciles.
Event Loop JavaScript, Python (asyncio), Rust (tokio) Un solo hilo que no espera: delega y retoma.
Hilos ligeros Go, Elixir, Kotlin Escribes código normal y el runtime reparte el trabajo.

En JavaScript, el Event Loop
no es opcional.

Es el único camino. Por eso, si bloqueas el hilo,
se congela toda la página.

Call Stack:

  • Es una pila LIFO (último en entrar, primero en salir).
  • Es donde se ven las funciones u operaciones que el hilo está ejecutando.
  • Es bloqueante PORQUE el hilo de JS solo puede hacer una cosa a la vez.

¿Verdadero o falso?

“setTimeout es parte de JavaScript.”

Falso.

Es una Web API: como el Event Loop, JS la heredó del navegador.
JavaScript solo le pide que cuente el tiempo.

Web APIs:

  • No son parte de JS.
  • Servicios del navegador que hacen trabajo en paralelo.
  • Timers, Network, DOM.

¿Qué va en las colas?

  • A la cola va el callback, no la llamada:
    la función que le pasas a setTimeout o a .then.
  • Ahí espera a que el Call Stack quede vacío y el Event Loop lo tome.

Microtask Queue:

  • Cola para Promises.
  • Se ejecutan TODOS por ciclo.
  • Prioridad ALTA.
  • Promise.resolve().then(() => {});
  • Promise.reject().catch(() => {});
  • queueMicrotask(() => {});

Macrotask Queue: (Callback queue)

  • Cola para Web APIs.
  • Se ejecuta UNO por ciclo.
  • Prioridad BAJA.
  • setTimeout(() => {}, 0);
  • setInterval(() => {}, 1000);
  • addEventListener('click', ...);

¿Verdadero o falso?

“Todo lo que está dentro de una Promise se ejecuta después.”

Falso.

Lo de dentro de new Promise(...) corre de inmediato. Solo lo del .then espera en la Microtask Queue.

new Promise((resolve) => {
  console.log("dentro"); // Sync
  resolve();
}).then(() => {
  console.log("then");   // Async
});

Event Loop:

  • Ciclo eterno que revisa si el Call Stack está vacío.
  • Es el vigilante que coordina TODO.
  • Sin él, JavaScript no sería asíncrono.

En resumen:

Call Stack Ejecuta el código, una cosa a la vez.
Web APIs Se encargan de lo que tarda: timers, fetch, eventos.
Colas de tareas Guardan los callbacks listos. Primero micro, luego macro.
Event Loop Si el Call Stack está vacío, le pasa el siguiente callback.

Cada vez que tu app se congela,
el Event Loop te está diciendo algo.

Las 3 reglas del Event Loop

  1. Primero se ejecuta todo el código síncrono.
  2. Luego, todas las microtasks (Promises), hasta vaciar la cola.
  3. Luego, una macrotask (setTimeout, eventos)… y vuelta a empezar.
